# 鸿蒙手机版 · 调研与设计（H1）

> 定位：**独立的司南产品**（不是 Mac 版移植）——鸿蒙 7 时代华为生态没有 Arc 式本地 AI 浏览器，差异化空间真实存在。Mac 版六项范围冻结不约束鸿蒙版，鸿蒙版的功能定义届时单独决策。

## 一、平台硬约束（调研结论）

| 项 | 结论 |
|---|---|
| 浏览器引擎 | **锁定 ArkWeb**——鸿蒙 NEXT 移除 AOSP 层，第三方浏览器不能自带 Chromium，必须用华为白名单化的 ArkWeb（Web 组件） |
| 开发者账号 | **华为账号免费**（对比 Apple $99/年） |
| 类目门槛 | 浏览器类目需要**专项资质审核**（公司主体 + 身份材料）——个人开发者能否过审是**第一道 go/no-go**，立项前先提交咨询 |
| 应用架构 | ArkTS + ArkUI 声明式 UI；无 APK 兼容层 |
| 端侧 AI | 两条路线：① 华为系统 AI（小艺/盘古 NPU 接口，零模型下载）② llama.cpp OpenHarmony 移植（自持模型，可控但需 NPU/CPU 调优） |
| 分发 | 华为应用市场（审核严于 Google Play） |

## 二、架构设计（草案）

```
司南鸿蒙版
├── ArkUI 壳（ArkTS）：侧栏式浏览 UI、命令栏、设置
├── ArkWeb 多实例池：双引擎等价物 = ArkWeb（主）+ Web 组件独立 profile
├── 核心逻辑层（从 CraCore 移植的算法，ArkTS 重写）：
│   ├── RRF 融合检索（纯数学，移植成本低）
│   ├── Tidy 两阶段/单遍分组 + 域规则学习（纯逻辑）
│   ├── 偏好记忆（tidy-prefs 结构兼容——与 Mac 端可互导）
│   └── 语义索引（embedding + 余弦，bge 类中文模型 ONNX/ adaptations）
├── 端侧 AI 路线（分层决策）：
│   ├── 第一期：系统 AI 接口（小艺能力）做翻译/摘要——零下载零维护
│   └── 第二期：llama.cpp OH 移植跑自研专用模型（与 W3 训练计划协同）
└── 平台协同（差异化主打）：
    ├── 服务卡片：今日浏览摘要 / 整理提醒
    ├── 蒸馏 → 华为笔记/备忘录生态
    └── 多设备协同：手机蒸馏 → 平板/PC 阅读（超级终端）
```

## 三、与 Mac 版的关系

- **共享的不是代码，是产品哲学与数据格式**：偏好记忆 JSON、笔记 frontmatter、模型目录结构保持兼容
- CraCore 的 Swift 代码不可直接复用（鸿蒙无 Swift 运行时）——移植工作量集中在**纯逻辑模块**（估算：检索/分组/索引 ≈ 3k 行 ArkTS）
- UI 全部重写（上游 200 个 SwiftUI 文件 ≠ ArkTS 成本可估，按同功能重做）

## 四、里程碑（意向性）

| 里程碑 | 内容 | 前置条件 |
|---|---|---|
| H0 | 资质咨询提交（浏览器类目专项审核）+ 华为开发者账号注册 | 用户决策 |
| H1 | ArkWeb 技术验证 demo：多标签 + 会话隔离 + 基本导航 | H0 过审意向 |
| H2 | 侧栏式 UI + 命令栏 + 历史（无 AI） | H1 |
| H3 | 端侧 AI 第一期（系统 AI 翻译/摘要） | H2 |
| H4 | 专用小模型移植（W3 成果的鸿蒙化） | H3 + W3 T4 |

## 五、风险

- **资质不确定**：浏览器是强管控类目；个人开发者过审未知 → H0 先行验证
- ArkWeb 能力面与 Chromium 有代差（扩展生态不存在）→ 鸿蒙版不承诺扩展，主打 AI + 轻浏览
- 端侧模型在手机 NPU 上的内存/功耗预算未知 → H3 用系统 AI 规避，H4 再评估
- 单人跨三端维护 → 鸿蒙版节奏必须落后 Mac 版一个稳定期

## 七、上游 iPhone 设计 = 鸿蒙版的设计参考库（2026-11-21 用户指示）

上游 2026-11-18~21 的 486-commit 冲刺主体是 **iPhone 端**（Arc Search 式交互）。虽然不同源（鸿蒙版是 ArkTS 重写），但这批设计是**现成的高质量移动端 Arc 式 UX 参考**——能借鉴的全部拿过来：

### 已观察到的可借鉴设计（486-commit 冲刺清单）

- **搜索联动**：手机搜索页拉起 Mac 的 Today 标签/Pinned in Space（跨设备 Arc Search 交互）→ 鸿蒙版对应：手机搜索联动 PC 司南
- **Peek 移动化**：侧栏地址栏 + ← → ↻ 直接驱动 Peek、卡片无栏设计 → 移动端轻预览交互
- **键盘随动**：搜索 sheet 随键盘起落贴顶
- **无痕模式图标在搜索框内的空间处理**
