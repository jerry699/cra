# 专用小模型训练计划（W3）

> 目标：训练一个 0.5–0.6B 多任务专用模型，替换默认 Qwen3-1.7B——在司南的全部六个 AI 任务上更快（预计 3-4×）、更准、体积减半（~350MB Q4）。
> 理论依据：六个任务格式全部固定（GBNF 约束解码），微调消除的是「指令遵循的随机性」而非「知识」——这正是小模型被通用基线拖垮的部分（OBS-3：0.6B 通用失败 = few-shot 复读）。

## 一、任务与数据

### 六个任务 = 六类样本

| 任务 | 输入→输出格式 | 数据来源 |
|---|---|---|
| Tidy Tabs（两阶段：topics / assignments） | 标签列表 → JSON 主题数 + 分配 | 用户真实 tidy-prefs（已有！`tidy-prefs-*.json`）+ 合成 |
| Tidy Tabs（单遍 grouped） | 标签列表 → `{"groups":[{name,ids}]}` | 同上 |
| Tidy Tab Titles | 原标题 → 简洁标题 | 用户真实 Pin 重命名记录（可从 cra.log 提取） |
| Tidy Downloads | 原文件名+页面 → 新文件名 | 用户真实下载 + 双语 few-shot 修正（OBS-3 中文→英文怪癖） |
| 划选翻译 | 原文 → 译文（CJK 双向） | 开源平行语料子集 + 真实翻译记录 |
| 蒸馏摘要 | 转写文本 → 要点 JSON | 真实蒸馏产物（用户 vault 里的笔记） |

### 数据主体是公开语料（2026-11-20 修正）

> 用户提出的质疑成立：个人 tidy-prefs 只反映一个人的习惯（量也太小），把它当训练主体会过拟合到个人——而司南的个性化设计本来就是**运行时注入**（域规则/few-shot 每次整理时进 prompt），个性化不进权重。一个模型服务所有用户。
>
> **个人数据的真实角色**：评测集（真实分布校准）+ 运行时个性化的种子——不参与训练。
>
> **训练主体 = 公开语料的「免费标签」**：中文互联网大量语料自带分类，天然合成 Tidy 任务——

- **THUCNews / CLUE 分类语料**（新闻 14 类目）：跨类目抽样文章标题 → 标题当「标签页」→ 原类目当「正确的组」。数万样本零标注
- **电商商品标题语料**：练 Tidy Downloads 重命名 + 商品词（摇粒绒/尺码类）
- **故意跨类目采样**：制造「完全不相关」负例（OBS-1 的 6:3:1 配比）
- **长→短标题改写对**：练 Tidy Tab Titles
- **LCSTS 短摘要语料**：练蒸馏要点输出
- **OPUS/WMT 平行语料抽样**：练划选翻译

### 数据配比与红线（OBS-1）

- **相关 : 部分相关 : 完全不相关 ≈ 6 : 3 : 1**——必须包含「互不相关标签集 → 输出空 groups/退避」样本，教会模型**合理退出**而不是硬凑（v0.1.91 单例组退化的教训）。
- 全部**简体中文**输出（OBS-3：消除中文→英文怪癖要从根上治）。
- few-shot 不再注入 prompt（微调后模型内化格式）——prompt 变短 = 推理更快。
- 每个 GBNF 语法变更 → 数据重生成（语法与权重必须同版本）。

### 合成管线（待建）

1. 脚本 `scripts/gen-training-data.py`：从公开分类语料合成对话样本，套六任务模板；真实 tidy-prefs 只做**评测集**（约 200 条）与分布校准
2. 反例工厂：跨类目采样互不相关标签集；单例陷阱样本；超长标题；重复站点
3. 人工抽检 5% 才入库

## 二、基建

- **训练**：AutoDL RTX 4090（~¥2/小时）。QLoRA（r=16-32）+ 4bit 量化基座，bf16 LoRA 权重。预计 3k-10k 样本 × 3 epoch = 2-6 小时/run（≈¥10-30）
- **基座**：Qwen3-0.6B（主）与 Qwen3-1.7B（对照）各训一版；转换 GGUF Q4_K_M
- **转换链**：LoRA 合并 → GGUF（llama.cpp convert）→ 每任务 GBNF 语法不变
- **部署**：进 ModelCatalog（`sha256` 固定，ModelScope+镜像双源），Max 页与现有模型并列展示，用户可选「专用版（快）」

## 三、评测（合格线）

1. **现有回归全绿**：recall-eval 语义路径不降；Tidy Titles ≥ 现基线
2. **新专项 eval**（待写 `scripts/tidy-eval.py`）：
   - 单例陷阱：全不相关输入 → 空组输出率 ≥ 95%（现 1.7B：0%）
   - 正常分组：10 标签 3 组任务准确率 ≥ 90%
   - Downloads：中文标题→中文名 ≥ 95%（现部分英化）
   - 翻译：BLEU/人工抽检 ≥ 1.7B
3. **速度**：1.7B 单遍 31s → 目标 ≤ 12s（0.6B + 短 prompt）
4. **真机冒烟**：GBNF 全任务跑通 + 6 标签真实场景

## 四、里程碑

| 里程碑 | 内容 | 预估 |
|---|---|---|
| T1 | 数据管线脚本 + 3k 样本合成 + 抽检 | 1 个会话 |
| T2 | 首次 QLoRA run（0.6B）+ GGUF 转换 | 1 个会话（含 AutoDL 环境） |
| T3 | 专项 eval 构建 + 首轮评测报告 | 1 个会话 |
| T4 | 迭代到合格线 + 真机灰度（Max 页可选） | 2-3 个会话 |

**开始条件**：用户确认 AutoDL 账号与预算；当前 tidy-prefs 数据量足够起步（用户已积累真实分类记忆）。

## 五、风险

- GGUF 转换后 GBNF 行为漂移 → 每次转换后全任务冒烟（已有教训：转换≠等价）
- 过拟合到用户个人习惯 → 混入合成多样性 + 公开语料
- 0.6B 蒸馏摘要质量可能不足 → 摘要任务可保留 1.7B 兜底（模型路由：小模型做格式任务，大模型做生成任务）

## 六、国内合规（关键，2026-11-20 增补）

背景：《生成式人工智能服务管理暂行办法》及 TC260 安全要求约束的是**面向公众的生成式 AI 服务**。司南的架构定位（本地离线模型、应用内下载、无云端服务）天然处于较有利的位置，但上架国内应用商店或运营下载站时，审核方可能仍要求提供证明或备案。应对策略分层记录如下：

1. **产品定位文档化**（已完成大半）：在 README/官网/应用内明确「模型本地运行、处理不出设备、不提供云端生成服务」。这是与「AI 服务提供者」区分的核心论据——我们分发的是工具与权重，用户在自己设备上运行。
2. **许可证审计（每次换模型/语料必须执行）**：
   - 基座许可证：Qwen3 系列 = Apache 2.0（可商用）；Belle 系列需查；任何商用分发前记录许可证全文
   - 语料许可证：**THUCNews 为学术研究用途**——若商用分发衍生权重，改用 LLM 合成数据（让大模型生成虚构标签页标题+分组）替代直接训练，或采购可商用语料。⚠️ 本条在 W3 启动时必须复核
   - 产出权重的许可证声明写入 Release
3. **备案路径预案**（届时按当时法规执行）：
   - 场景 A：仅 GitHub/Gitee 开源分发权重 → 现行实践中开源权重普遍无需大模型备案，保留定位文档即可
   - 场景 B：上架国内应用商店（内置 AI 功能）→ 商店可能要求「生成式AI应用备案」或算法备案截图——路径：以应用开发者身份做互联网信息服务算法备案（本地模型 + 不含舆论属性输入的声明从宽处理，届时咨询）
   - 场景 C：官网集成任何云端 AI 服务 → 触发服务提供者义务，需大模型备案——**当前架构刻意避免此场景**
4. **训练与发布留痕**：数据来源、许可证、合成方法全部在本文档与 Release 说明留痕，备查。

## 七、新增需求记录（2026-11-20）

- **macOS 12 支持**：当前部署目标 macOS 14。降级可行性待研究（SwiftUI API、CEF 最低系统、Sparkle 2 要求）；作为 0.4.x 候选。见 ROADMAP。
- **8GB 内存机型**：训练/引入 ~0.3-0.5B 更小模型（Qwen2.5-0.5B 级），Q4 量化 ~350MB，8GB 内存可跑「AI 基本功能」（标题整理+翻译）。列入 W3 扩展目标。

## 八、首轮训练复盘与 v2 计划（2026-11-20，v0.3.00 发布后）

### 首轮结果（run-1）

| 项 | 值 |
|---|---|
| 实例 | 4090 SUPER 32GB（vGPU-32GB ¥1.58/时），云上全程 |
| 数据 | 3600 条（tabs-grouped 1800 / tab-title 583 / download-name 569 / translate 600 / unrelated-空组占比 ~11%） |
| 训练 | 642 步 × 3 epochs，**6.5 分钟完成**，LoRA 40MB |
| 评测 | 正常分组 ✅ 完美；单例陷阱 ✗ 强行分组；标题简化 ⚠️ 促销词未清除 |

### 教训 → v2 修正

1. **弃权技能**：unrelated 样本与正常样本用同一指令训练，模型学不出「何时弃权」。且生产中 CraCore prompt 恒定严格——模型永远会输出分组。**结论：单例陷阱降级为低优先**（下游 plan() 本就丢弃 <2 标签的组，最坏情况=分组质量一般，不产生系统故障）；改为训练「部分相关集合里把无关标签归入最接近的组」，贴合生产分布。
2. **标题任务强化（v2 主修）**：样本 583→1200；清洗目标改为三段式（去站名→去促销词【新品首发/官方正品/限时优惠】→保留产品词+类目词）；加入商品标题语料的脏样本。
3. **组名同义池已验证有效**（18 个唯一组名）——保留并扩充。
4. **数据量**：3600→4500（tabs 1800 不变，title 583→1200，download 569→800，translate 600 不变）。
5. **epochs**：首轮 3 epochs 642 步无过拟合迹象（loss 平稳下降）——v2 保持 3 epochs。

### 成本核算（run-1 实测）

实例 1.58 时 × 约 1 小时（含环境安装 11 分钟模型下载 + 训练 6.5 分钟 + 评测推理）≈ **¥1.6**。v2 预估 ¥3-4（含训练 25 分钟与评测推理）。远低于预算。

## 九、部署提速：自定义镜像（2026-11-20 增补）

今天部署耗时约 40 分钟（装依赖 15 分钟 + 版本冲突调试 25 分钟）。AutoDL 的「保存镜像」功能可把下次部署压缩到 **2 分钟**：

### 首次训练后的标准动作（已完成配置的实例，创建新实例前执行）

控制台 → 实例 → 更多 → **保存镜像**（命名如 `sinan-train-v1`）——把装好
torch/transformers 4.51.3/peft/accelerate + 已下载 Qwen3-0.6B 的环境整个打包。

### 下次训练的部署路径（二选一）

| 路径 | 耗时 | 操作 |
|---|---|---|
| **我的镜像**（推荐） | **~2 分钟** | 创建实例 → 镜像区选「我的镜像」→ sinan-train-v1 → 开机即全套环境就绪（含模型文件） |
| 重新部署 | ~20 分钟 | 基础镜像 + 重跑 setup（装依赖 15 分钟 + 模型下载 5 分钟） |

### 注意

- 经典实例「连续关机 15 天后释放」——训练间隔若超 15 天，务必先保存镜像
- 释放实例 = 环境全丢，**只有保存过镜像才可恢复**
- 模型/数据盘文件（/root/autodl-tmp）不随保存镜像走——base model 已打进镜像的话无碍；训练产物（LoRA）训练完立即取回本地
- 环境版本组合（transformers 4.51.3 + hub 0.30.0 + peft 0.15.2 + accelerate 1.6.0，无 datasets）是调试出的**唯一可用组合**——保镜像避免重踩

### 配套：T2 驱动脚本已支持

`scripts/autodl-t2.py` 的 create/setup/upload/train/status/fetch 全流程命令化；
下次训练实际操作序列：
```
create（改 IMAGE 为我的镜像 UUID）
upload
train      # ~25 分钟
status     # 观察进度

```
